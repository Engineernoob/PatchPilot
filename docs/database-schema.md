# Database Schema

## Overview

PatchPilot stores incidents, uploaded evidence, AI-generated analyses, and supporting metadata in a PostgreSQL database.

The schema is designed to keep raw debugging evidence separate from generated AI outputs while maintaining clear relationships between incidents and their analysis.

---

## Entity Relationship Overview

```text
incidents
    │
    ├──────────────┐
    │              │
    ▼              ▼
evidence      hypotheses
                     │
                     ▼
              fix_suggestions
```

---

## incidents

The `incidents` table represents a single debugging session.

### Purpose

Stores the primary metadata for each incident and serves as the parent record for uploaded evidence and AI-generated results.

### Key Fields

| Field       | Type      | Description                 |
| ----------- | --------- | --------------------------- |
| id          | UUID      | Unique incident identifier  |
| title       | TEXT      | Short incident title        |
| description | TEXT      | User-provided description   |
| severity    | TEXT      | Incident severity           |
| status      | TEXT      | Current processing status   |
| created_at  | TIMESTAMP | Creation timestamp          |
| updated_at  | TIMESTAMP | Last modification timestamp |

---

## evidence

Stores all uploaded debugging artifacts associated with an incident.

### Supported Evidence Types

- Log files
- Stack traces
- Screenshots
- Bug reports
- Console output

### Key Fields

| Field             | Type      | Description              |
| ----------------- | --------- | ------------------------ |
| id                | UUID      | Evidence identifier      |
| incident_id       | UUID      | Parent incident          |
| type              | TEXT      | Evidence type            |
| content           | TEXT      | Original evidence        |
| normalized_signal | JSONB     | Structured parser output |
| uploaded_at       | TIMESTAMP | Upload timestamp         |

---

## hypotheses

Stores AI-generated root-cause hypotheses.

### Key Fields

| Field       | Type    | Description            |
| ----------- | ------- | ---------------------- |
| id          | UUID    | Hypothesis identifier  |
| incident_id | UUID    | Related incident       |
| rank        | INTEGER | Display order          |
| confidence  | FLOAT   | Confidence score       |
| explanation | TEXT    | AI-generated reasoning |
| evidence    | JSONB   | Supporting evidence    |

---

## fix_suggestions

Stores remediation recommendations generated by the AI pipeline.

### Key Fields

| Field          | Type | Description                |
| -------------- | ---- | -------------------------- |
| id             | UUID | Suggestion identifier      |
| incident_id    | UUID | Parent incident            |
| hypothesis_id  | UUID | Related hypothesis         |
| recommendation | TEXT | Suggested fix              |
| commit_message | TEXT | Draft Git commit message   |
| pr_summary     | TEXT | Draft pull request summary |

---

## Relationships

- One incident can have many evidence records.
- One incident can produce many hypotheses.
- One hypothesis can produce multiple suggested fixes.

---

## Design Considerations

The schema is designed with the following goals:

- Preserve raw debugging evidence.
- Store normalized parser output separately.
- Keep AI-generated artifacts independent of original evidence.
- Support future retrieval and evaluation workflows.
- Allow multiple analysis runs for the same incident in future versions.
